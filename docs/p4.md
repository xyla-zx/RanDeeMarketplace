### 9.2 สเปกคอมโพเนนต์หลัก

#### Button

```tsx
type ButtonProps = {
  variant?: 'primary' | 'secondary' | 'ghost' | 'danger' | 'outline'
  size?: 'sm' | 'md' | 'lg'
  icon?: IconName            // ไอคอนนำหน้า
  iconEnd?: IconName
  loading?: boolean          // แสดง Spinner แทน icon และ disable
  fullWidth?: boolean
  asChild?: boolean          // ใช้กับ Link
} & React.ButtonHTMLAttributes<HTMLButtonElement>
```

| variant | พื้น | ตัวอักษร | ขอบ | hover | ใช้เมื่อ |
|---|---|---|---|---|---|
| primary | cobalt-600 | ขาว | ไม่มี | cobalt-700 | การกระทำหลักของหน้า (มีได้หน้าละ 1) |
| secondary | enamel | ink-950 | 1px rim-strong | glaze + ขอบ ink-400 | การกระทำรอง |
| outline | โปร่ง | cobalt-600 | 1.5px cobalt-600 | cobalt-50 | การกระทำรองที่ต้องเด่น |
| ghost | โปร่ง | ink-700 | ไม่มี | ink-100 | ในแถบเครื่องมือ |
| danger | rooster-600 | ขาว | ไม่มี | rooster-700 | ลบ ระงับ ยกเลิก |

ขนาด: `sm` สูง 34px padding 12px ตัวอักษร 14px · `md` สูง 42px padding 16px 15px
· `lg` สูง 50px padding 22px 16px (ปุ่มหลักบนมือถือใช้ `lg` + `fullWidth` เสมอ)

กฎ:
- ข้อความปุ่มเป็นกริยาวลีที่บอกผลลัพธ์ ห้ามใช้คำว่า "ยืนยัน" "ตกลง" ลอย ๆ
- ห้ามใส่ `→` ท้ายข้อความ
- ปุ่มที่ทำงานนานต้องเปลี่ยนเป็น `loading` และข้อความเป็นรูปกำลังทำ เช่น "กำลังเผยแพร่"
- ปุ่มอันตรายต้องมีขั้นยืนยันเสมอ ยกเว้นมี undo ภายใน 10 วินาที
- พื้นที่แตะบนมือถือต้องไม่น้อยกว่า 44x44px แม้ปุ่มจะเล็กกว่านั้น (ใช้ pseudo element ขยาย)

#### Input / Field

โครงสร้าง: `<label>` เหนือช่อง ไม่ใช้ placeholder แทน label เด็ดขาด

```
ชื่อโพสต์                         (label 14px/500, ink-800)
┌──────────────────────────────┐
│ ชุดเดรสผ้าลินินสีครีม              │  สูง 44px, พื้นขาว, ขอบ 1px rim
└──────────────────────────────┘  โฟกัส: ขอบ cobalt-600 + ring 3px
ระบุสี ไซซ์ และวัสดุ จะขายดีกว่า 40%    (help 12px, ink-600)
```

สถานะ: `default` `focus` `filled` `error` `disabled` `readonly`
- `error`: ขอบ rooster-600, ข้อความช่วยเปลี่ยนเป็นข้อความผิดพลาดสี rooster-600
  พร้อมไอคอน `alert` ขนาด 16 และ `aria-invalid="true"` `aria-describedby`
- ช่องที่จำเป็นใส่ดอกจันหลัง label สี rooster-600 และ `required`
- ช่องราคาแสดง `฿` เป็น prefix ในกรอบ และรับเฉพาะตัวเลข ใส่คั่นหลักพันอัตโนมัติ
- ช่องที่มีขีดจำกัดตัวอักษรแสดงตัวนับมุมขวาล่าง เปลี่ยนเป็นสีแดงเมื่อเหลือ < 10%

#### ListingCard

การ์ดสินค้าในฟีด เป็นคอมโพเนนต์ที่ผู้ใช้เห็นบ่อยที่สุด ต้องเบาที่สุด

```
┌────────────────────┐
│                    │  รูป 4:5, radius-img 4px บนซ้าย/ขวา
│      รูปสินค้า        │  มี blurhash placeholder
│                    │  มุมซ้ายบน: ป้าย "ลด 32%" (ถ้ามี)
│                ♡   │  มุมขวาบน: ปุ่มบันทึก (ไอคอน bookmark)
├────────────────────┤
│ ชื่อสินค้าสองบรรทัดสูงสุด  │  14px/1.45, ink-900, line-clamp 2
│ ┌──────────┐        │
│ │ ฿ 1,290  │        │  ป้ายราคาทรงตั๋วขนาด sm
│ └──────────┘        │
│ ฿1,890 ลด 32%       │  ราคาเดิมขีดฆ่า + ส่วนลด (rooster)
│ ──────────────────  │  เส้นคั่น rim
│ [โลโก้] ชื่อร้าน  ✓     │  12px ink-600 + ไอคอน verified ถ้ามี
│ กรุงเทพฯ · 2 ชม.      │  ระยะทางถ้ามีพิกัด ไม่งั้นแสดงจังหวัด
└────────────────────┘
```

กฎ:
- การ์ดไม่มีเงา ใช้ขอบ 1px rim และพื้นขาว
- ทั้งการ์ดเป็นลิงก์เดียว ยกเว้นปุ่มบันทึกที่ `stopPropagation`
- โหลดรูปแบบ lazy ยกเว้น 4 ใบแรกให้ `priority`
- `content-visibility: auto` และ `contain-intrinsic-size` เพื่อไม่ให้ layout กระตุก
- มีโหมด `compact` (แนวนอน) สำหรับผลค้นหาแบบรายการและหน้าประวัติ
- มีสถานะ `sold` : รูปเป็นขาวดำ 60% + แถบทับกลางรูปว่า "ขายแล้ว"

#### StatusPill

ใช้แสดงสถานะออเดอร์ โพสต์ ร้าน และคำขอถอนเงิน
พื้นเป็นสีอ่อน 100 ตัวอักษรสี 700 ไม่มีขอบ radius-chip ตัวอักษร 12px/500
มีจุดสีนำหน้าขนาด 6px

```
รอชำระเงิน  = amber      ชำระแล้ว    = cobalt     กำลังเตรียม = cobalt
จัดส่งแล้ว   = kraft      ส่งถึงแล้ว    = jade       สำเร็จ      = jade
ยกเลิก      = ink-500    คืนเงิน      = ink-500    ข้อพิพาท     = rooster
```

#### ImageUploader

หัวใจของประสบการณ์ผู้ขาย ต้องทำงานได้ดีบนมือถือเน็ตช้า

ข้อกำหนด:
1. เลือกได้สูงสุด 10 รูป ลากสลับลำดับได้ทั้งเมาส์และนิ้ว (ใช้ `@dnd-kit`)
2. รูปแรกคือรูปปก มีป้าย "ปก" ทับมุมซ้ายบน
3. บีบอัดฝั่ง client ก่อนอัปโหลด: ย่อด้านยาวสุดเหลือ 1600px คุณภาพ 0.82 เป็น WebP
4. อัปโหลดขนานได้ 3 ไฟล์ มี progress ต่อไฟล์ ยกเลิกรายไฟล์ได้
5. อัปโหลดล้มเหลวต้องกด "ลองใหม่" ได้ ไม่ต้องเลือกไฟล์ใหม่
6. เครื่องมือในตัว: หมุน 90°, ครอปเป็น 4:5 / 1:1, ลบพื้นหลัง (Phase 2)
7. รับไฟล์: jpeg, png, webp, heic (แปลง heic เป็น jpeg ฝั่ง client)
8. ปฏิเสธไฟล์ > 12MB พร้อมข้อความบอกขนาดจริง
9. แสดงคำเตือนถ้ารูปเบลอ (ตรวจด้วย Laplacian variance ฝั่ง client)

#### OrderTimeline

เส้นเวลาแนวตั้งของออเดอร์ แต่ละขั้นมี: ไอคอน, ชื่อสถานะ, เวลา, ข้อความอธิบาย

```
 ●  สั่งซื้อแล้ว              12 มี.ค. 68 14:32
 │  รอผู้ขายยืนยันภายใน 24 ชม.
 ●  ผู้ขายรับออเดอร์            12 มี.ค. 68 15:10
 │
 ●  จัดส่งแล้ว               13 มี.ค. 68 09:45
 │  Flash Express · TH123456789  [คัดลอก]
 ○  ถึงมือผู้รับ                คาดว่า 14 มี.ค.
 │
 ○  ยืนยันรับของ
```

- จุดที่ผ่านแล้วทึบสี cobalt, ที่ยังไม่ถึงเป็นวงกลมกลวงสี rim-strong
- ขั้นที่เป็นปัญหา (ยกเลิก/พิพาท) เปลี่ยนเป็นสี rooster และตัดเส้นที่เหลือทิ้ง
- บนมือถือ เลขพัสดุมีปุ่มคัดลอกและปุ่มเปิดหน้าติดตามของ carrier

#### EmptyState

```tsx
type EmptyStateProps = {
  illustration: 'shelf' | 'basket' | 'search' | 'chat' | 'parcel' | 'bell'
  title: string           // ประโยคเดียว ไม่เกิน 40 ตัวอักษร
  description?: string    // ไม่เกิน 2 บรรทัด บอกว่าทำอะไรต่อได้
  action?: { label: string; href?: string; onClick?: () => void }
  secondaryAction?: { label: string; href: string }
}
```

จัดกึ่งกลางแนวตั้งในพื้นที่ที่เหลือ ภาพประกอบ 160x120 เว้น 20px ก่อนหัวข้อ

#### Toast

- ตำแหน่ง: มือถือชิดล่างเหนือแถบนำทาง 12px, เดสก์ท็อปมุมขวาล่าง
- แสดงพร้อมกันสูงสุด 3 อัน อันเก่าสุดหายก่อน
- อายุ 4 วินาที (มี action ยืดเป็น 8 วินาที) หยุดนับเมื่อ hover หรือ focus
- ชนิด: `success` (ไอคอน checkCircle สี jade) `error` (alert สี rooster)
  `info` (info สี cobalt) `undo` (มีปุ่ม "เลิกทำ")
- ห้ามใช้ toast บอกข้อผิดพลาดของฟอร์ม ให้แสดงในฟอร์มแทน
- `role="status"` สำหรับ success/info, `role="alert"` สำหรับ error

### 9.3 กฎการเขียนคอมโพเนนต์

```tsx
// แม่แบบที่ทุกคอมโพเนนต์ต้องทำตาม
import { cva, type VariantProps } from 'class-variance-authority'
import { cn } from '@randee/ui/lib/cn'

const button = cva(
  'inline-flex items-center justify-center gap-2 rounded-[var(--radius-btn)] ' +
  'font-medium transition-colors duration-[var(--dur-fast)] ' +
  'focus-visible:outline-none focus-visible:ring-[3px] focus-visible:ring-cobalt-600/30 ' +
  'focus-visible:border-cobalt-600 disabled:pointer-events-none disabled:opacity-50',
  {
    variants: {
      variant: { /* … */ },
      size: { /* … */ },
      fullWidth: { true: 'w-full' },
    },
    defaultVariants: { variant: 'secondary', size: 'md' },
  }
)

export type ButtonProps = VariantProps<typeof button> &
  React.ButtonHTMLAttributes<HTMLButtonElement> & { icon?: IconName }

export const Button = React.forwardRef<HTMLButtonElement, ButtonProps>(
  function Button({ className, variant, size, fullWidth, icon, children, ...rest }, ref) {
    return (
      <button ref={ref} className={cn(button({ variant, size, fullWidth }), className)} {...rest}>
        {icon ? <Icon name={icon} size={size === 'sm' ? 16 : 20} /> : null}
        {children}
      </button>
    )
  }
)
```

ทุกคอมโพเนนต์ต้อง: `forwardRef`, รับ `className` มาผสมได้, ไม่ผูกกับ data fetching,
มี story ใน `packages/ui/stories/*.stories.tsx`, มี test การเข้าถึงด้วย `axe`

### 9.4 สถานะการโหลด

ห้ามใช้ spinner กลางจอเป็นค่าเริ่มต้น ใช้ตามลำดับนี้:

1. **Skeleton** สำหรับเนื้อหาที่รู้รูปร่างล่วงหน้า (ฟีด การ์ด ตาราง) — ใช้ในทุกหน้าหลัก
   สีพื้น `ink-100` ไม่มี shimmer วิ่ง (ใช้ opacity เต้นช้า 1.6 วินาทีแทน เพื่อลด GPU)
2. **Inline spinner** ในปุ่มที่กด
3. **ProgressBar** บนสุดของหน้า สำหรับการนำทาง (ใช้ `next/navigation` + nprogress แบบเขียนเอง)
4. **Optimistic UI** สำหรับ: กดบันทึกโพสต์, กดถูกใจ, ส่งข้อความแชท, เพิ่มลงตะกร้า
   ถ้าล้มเหลวให้ย้อนกลับพร้อม toast แบบ error
