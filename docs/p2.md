### 4.5 กฎการวางโค้ด

1. **Server Component เป็นค่าเริ่มต้น** ใส่ `'use client'` เฉพาะไฟล์ที่ต้องใช้ state/effect/event จริง ๆ
2. ไฟล์ `'use client'` ต้องไม่เกิน 200 บรรทัด ถ้าเกินให้แตกเป็น component ย่อย
3. การเขียนข้อมูลใช้ **Server Action** เท่านั้น ยกเว้นที่ต้องเรียกจากภายนอกให้ทำเป็น route handler
4. Server Action ทุกตัวขึ้นต้นด้วย 4 บรรทัดนี้เสมอ:
   ```ts
   'use server'
   const session = await requireSession()            // โยน error ถ้าไม่ล็อกอิน
   const input = Schema.parse(raw)                   // Zod
   await assertCan(session, 'listing:update', input.id)  // RBAC
   await rateLimit(`listing:update:${session.userId}`, 30, '1m')
   ```
5. Business logic ห้ามอยู่ใน component ให้อยู่ใน `server/services/*` และต้องเขียน unit test ได้โดยไม่ต้องมี Next.js
6. การเข้าถึงฐานข้อมูลทำผ่าน service เท่านั้น ห้าม import `prisma` ตรงใน component
7. ชื่อไฟล์ใช้ `kebab-case.ts` ชื่อ component ใช้ `PascalCase` ชื่อ hook ขึ้นต้น `use`
8. ห้าม default export ยกเว้นไฟล์ที่ Next.js บังคับ (page, layout, route, error)

### 5.2 Domain Event

ทุกการกระทำสำคัญต้องปล่อย event ลงตาราง `OutboxEvent` ใน transaction เดียวกับการเขียนข้อมูล
แล้วให้ worker อ่านไปประมวลผล (transactional outbox pattern) เพื่อไม่ให้เกิดกรณี
"เขียน DB สำเร็จแต่ส่งแจ้งเตือนไม่สำเร็จ"

รายการ event ที่ต้องมี:

```

shop.suspended             listing.drafted           listing.published
listing.updated            listing.sold_out          listing.expired
listing.takedown           listing.boosted           search.saved_matched
chat.message_sent          chat.offer_made           chat.offer_accepted
order.placed               order.paid                order.accepted
order.packed               order.shipped             order.delivered
order.completed            order.cancelled           order.refunded
```

### 5.3 งานพื้นหลัง (BullMQ queues)

| คิว | ความถี่ | หน้าที่ |
|---|---|---|
| `outbox` | ทุก 1 วินาที | อ่าน OutboxEvent ที่ยังไม่ส่ง แล้ว dispatch |
| `media` | ตามงาน | ย่อรูป สร้าง AVIF/WebP, blurhash, ตรวจรูปไม่เหมาะสม |
| `search-index` | ตามงาน | sync listing/shop เข้า Meilisearch |
| `notification` | ตามงาน | ส่ง in-app / push / email / SMS ตาม matrix |
| `shipping-poll` | ทุก 30 นาที | ถามสถานะพัสดุจาก carrier ที่ไม่มี webhook |
| `escrow-release` | ทุกชั่วโมง | ปล่อยเงินออเดอร์ที่ครบกำหนดอัตโนมัติ |
| `listing-expire` | ทุกชั่วโมง | ปิดโพสต์ที่หมดอายุ แจ้งเจ้าของให้ต่ออายุ |
| `boost-expire` | ทุก 10 นาที | ปิดการดันที่หมดเวลา |
| `payout-batch` | วันละครั้ง 14:00 | รวมคำขอถอนแล้วส่งธนาคาร |

| `cleanup` | วันละครั้ง 03:00 | ลบร่างเก่า > 60 วัน, ไฟล์กำพร้า, session หมดอายุ |

### 5.5 สถานะฝั่ง client

ใช้ URL เป็นที่เก็บสถานะเป็นหลัก (ตัวกรอง หน้า การเรียงลำดับ แท็บ) เพื่อให้แชร์ลิงก์ได้
ใช้ Zustand ได้เพียง 3 กรณีเท่านั้น:

1. `useComposerStore` — ร่างโพสต์ที่กำลังเขียน (บันทึกลง IndexedDB ด้วย)
2. `useCartStore` — ตะกร้าก่อนล็อกอิน (ย้ายขึ้น server เมื่อล็อกอิน)
3. `useChatStore` — ข้อความที่กำลังส่งและสถานะการพิมพ์

### 5.6 การจัดการเงิน

```ts
// lib/money.ts — ใช้ไฟล์นี้เท่านั้นในการคำนวณเงิน
export type Satang = number & { readonly __brand: 'Satang' }

export const satang = (n: number): Satang => {
  if (!Number.isInteger(n)) throw new Error('Money must be an integer in satang')
  return n as Satang
}
export const fromBaht = (baht: number): Satang => satang(Math.round(baht * 100))
export const toBaht = (s: Satang): number => s / 100
export const formatTHB = (s: Satang, locale = 'th-TH'): string =>
  new Intl.NumberFormat(locale, {
    style: 'currency', currency: 'THB',
    minimumFractionDigits: s % 100 === 0 ? 0 : 2,
  }).format(toBaht(s))

// คิดค่าธรรมเนียมแบบปัดเศษลงเสมอ ส่วนต่างตกเป็นของผู้ขาย
export const feeOf = (amount: Satang, bps: number): Satang =>
  satang(Math.floor((amount * bps) / 10_000))
```

**กฎ**: ทุกตัวเลขเงินใน Prisma เป็น `Int` ชื่อ field ลงท้ายด้วย `Satang` เสมอ
เช่น `priceSatang`, `shippingFeeSatang`, `totalSatang`
