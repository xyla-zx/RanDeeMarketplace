## 11. สัญญา API

### 11.0 หลักการทั่วไป

- เส้นทางขึ้นต้น `/api/v1/` ทุกอัน คืน JSON เท่านั้น
- ใช้ `Content-Type: application/json` ยกเว้นการอัปโหลดที่ใช้ presigned URL ตรงไป S3
- เวลาเป็น ISO 8601 UTC พร้อม `Z`
- เงินเป็นจำนวนเต็มสตางค์ ชื่อฟิลด์ลงท้าย `Satang`
- ทุก response มีโครงเดียวกัน:

```jsonc
// สำเร็จ
{ "data": { … }, "meta": { … } }

// สำเร็จแบบรายการ
{
  "data": [ … ],
  "meta": { "nextCursor": "cmb…", "hasMore": true, "total": 1240 }
}

// ผิดพลาด
{
  "error": {
    "code": "LISTING_OUT_OF_STOCK",
    "message": "สินค้าชิ้นนี้เหลือไม่พอ",
    "messageEn": "Not enough stock for this item",
    "field": "items[0].quantity",
    "details": { "available": 2, "requested": 5 },
    "traceId": "01J8…"
  }
}
```

- แบ่งหน้าแบบ cursor เสมอ (`?cursor=&limit=` โดย `limit` สูงสุด 50 ค่าเริ่มต้น 20)
  ยกเว้นหลังบ้านที่ใช้ offset ได้เพราะต้องกระโดดหน้า
- ทุกคำขอเขียนข้อมูลต้องส่ง `Idempotency-Key` header สำหรับ endpoint การเงิน

### 11.1 รหัสข้อผิดพลาดมาตรฐาน

| HTTP | code | ความหมาย |
|---|---|---|
| 400 | `VALIDATION_FAILED` | ข้อมูลไม่ผ่าน Zod มี `details.issues[]` |
| 401 | `UNAUTHENTICATED` | ไม่ได้ล็อกอินหรือ session หมดอายุ |
| 403 | `FORBIDDEN` | ล็อกอินแล้วแต่ไม่มีสิทธิ์ |
| 403 | `SHOP_SUSPENDED` | ร้านถูกระงับ |
| 403 | `PLAN_LIMIT_REACHED` | เกินโควตาของแผน มี `details.limit` |
| 404 | `NOT_FOUND` | |
| 409 | `SLUG_TAKEN` | ชื่อ URL ซ้ำ |
| 409 | `LISTING_OUT_OF_STOCK` | |
| 409 | `ORDER_STATE_INVALID` | เปลี่ยนสถานะไม่ถูกลำดับ มี `details.from`,`details.allowed[]` |
| 409 | `PAYMENT_ALREADY_PROCESSED` | |
| 422 | `PAYMENT_DECLINED` | มี `details.providerCode` |
| 422 | `INSUFFICIENT_BALANCE` | |
| 429 | `RATE_LIMITED` | มี header `Retry-After` |
| 451 | `CONTENT_BLOCKED` | เนื้อหาผิดกฎ |
| 500 | `INTERNAL_ERROR` | ไม่เปิดเผยรายละเอียด ให้ log ด้วย `traceId` |
| 503 | `SERVICE_UNAVAILABLE` | ปลายทางภายนอกล่ม |

**กฎ**: ข้อความ `message` ต้องเป็นสิ่งที่แสดงต่อผู้ใช้ได้ทันที ห้ามส่ง stack trace
ห้ามส่งชื่อตาราง/คอลัมน์ออกไปนอกระบบ

### 11.3 ตัวอย่าง Zod schema ร่วม

```ts
// packages/contracts/src/listing.ts
import { z } from 'zod'

export const ListingCreateSchema = z.object({
  title: z.string().trim().min(8, 'ตั้งชื่อให้ยาวกว่านี้อีกหน่อย').max(140),
  description: z.string().trim().min(20).max(5000),
  categoryId: z.string().cuid(),
  condition: z.enum(['NEW','LIKE_NEW','GOOD','FAIR','FOR_PARTS']),
  type: z.enum(['PRODUCT','SERVICE','SECONDHAND','PREORDER']).default('PRODUCT'),
  priceSatang: z.number().int().min(100, 'ราคาต่ำสุด 1 บาท').max(100_000_000),
  comparePriceSatang: z.number().int().positive().optional(),
  isNegotiable: z.boolean().default(false),
  minOfferSatang: z.number().int().positive().optional(),
  quantity: z.number().int().min(0).max(9999).default(1),
  mediaIds: z.array(z.string().cuid()).min(1, 'ใส่รูปอย่างน้อย 1 รูป').max(10),
  variants: z.array(z.object({
    name: z.string().max(60),
    options: z.record(z.string()),
    priceSatang: z.number().int().positive().optional(),
    quantity: z.number().int().min(0),
    sku: z.string().max(40).optional(),
    mediaId: z.string().cuid().optional(),
  })).max(60).default([]),
  attributes: z.record(z.union([z.string(), z.number(), z.boolean(), z.array(z.string())])).default({}),
  tags: z.array(z.string().max(40)).max(10).default([]),
  weightGram: z.number().int().positive().max(50_000).optional(),
  shippingMode: z.enum(['FREE','SELLER_RATE','FLAT_RATE','CARRIER_CALCULATED','PICKUP_ONLY']),
  allowCod: z.boolean().default(true),
  scheduledAt: z.coerce.date().optional(),
})
.refine(v => !v.comparePriceSatang || v.comparePriceSatang > v.priceSatang,
  { path: ['comparePriceSatang'], message: 'ราคาก่อนลดต้องมากกว่าราคาขาย' })
.refine(v => !v.isNegotiable || !!v.minOfferSatang,
  { path: ['minOfferSatang'], message: 'ระบุราคาต่ำสุดที่รับได้' })
.refine(v => v.variants.length === 0 || v.variants.every(x => x.quantity >= 0),
  { path: ['variants'], message: 'จำนวนต้องไม่ติดลบ' })

export type ListingCreateInput = z.infer<typeof ListingCreateSchema>
```

### 11.4 ตาราง RBAC

`assertCan(session, action, resourceId)` ต้องเช็คตามตารางนี้เท่านั้น
เจ้าของ = `resource.ownerId === session.userId`

| การกระทำ | GUEST | MEMBER | SELLER(เจ้าของ) | MODERATOR | SUPPORT | FINANCE | ADMIN |
|---|---|---|---|---|---|---|---|
| ดูโพสต์ที่เผยแพร่ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| ดูร่างโพสต์ | – | – | ✓ | ✓ | – | – | ✓ |
| สร้าง/แก้โพสต์ | – | – | ✓ | – | – | – | ✓ |
| ลบโพสต์ | – | – | ✓ | ✓ | – | – | ✓ |
| ระงับโพสต์ | – | – | – | ✓ | – | – | ✓ |
| สร้างร้าน | – | ✓ | – | – | – | – | ✓ |
| แก้ข้อมูลร้าน | – | – | ✓ | – | – | – | ✓ |
| ระงับร้าน | – | – | – | ✓ | – | – | ✓ |
| ดูข้อมูล KYC | – | – | ✓(ของตัวเอง) | ✓ | – | ✓ | ✓ |
| สั่งซื้อ | – | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| ดูออเดอร์ | – | ✓(ของตัวเอง) | ✓(ของร้าน) | – | ✓ | ✓ | ✓ |
| เปลี่ยนสถานะออเดอร์ | – | ✓(บางสถานะ) | ✓ | – | ✓ | – | ✓ |
| คืนเงิน | – | – | – | – | ✓(≤2,000฿) | ✓ | ✓ |
| ตัดสินข้อพิพาท | – | – | – | – | ✓ | – | ✓ |
| อนุมัติถอนเงิน | – | – | – | – | – | ✓ | ✓ |
| ดูรายงาน/คิว | – | – | – | ✓ | ✓ | – | ✓ |
| แก้หมวดหมู่/แบนเนอร์/CMS | – | – | – | – | – | – | ✓ |
| ดู audit log | – | – | – | ✓(อ่าน) | ✓(อ่าน) | ✓(อ่าน) | ✓ |
| เปลี่ยนสิทธิ์ผู้ใช้ | – | – | – | – | – | – | ✓ |

กฎเสริม:
- ผู้ใช้สถานะ `RESTRICTED` ทำได้เฉพาะการอ่านและการซื้อ
- ร้านสถานะ `SUSPENDED` โพสต์ถูกซ่อนจากฟีดแต่เจ้าของยังเห็นและตอบแชทออเดอร์เดิมได้
- การกระทำของ MODERATOR ขึ้นไปทุกครั้งต้องเขียน `AuditLog` พร้อม `reason`
- ห้ามให้ role ใดแก้ข้อมูลธนาคารของร้านอื่นได้ รวมถึง ADMIN (ต้องผ่านคำขอจากเจ้าของ + OTP)

### 11.5 ขีดจำกัดอัตราการเรียก

ใช้ sliding window บน Redis คีย์เป็น `userId` ถ้าล็อกอิน ไม่งั้นใช้ IP + fingerprint

| กลุ่ม | ขีดจำกัด |
|---|---|
| ขอ OTP | 3 ครั้ง/10 นาที ต่อเบอร์, 10 ครั้ง/ชม. ต่อ IP |
| ยืนยัน OTP | 5 ครั้ง/รหัส แล้วล็อก 15 นาที |
| เข้าสู่ระบบ | 8 ครั้ง/15 นาที ต่อ identifier |
| สร้างโพสต์ | 30 ครั้ง/วัน (แผนฟรี), 200 ครั้ง/วัน (แผนธุรกิจ) |
| ดันโพสต์ฟรี | 1 ครั้ง/โพสต์/วัน และ 5 ครั้ง/ร้าน/วัน |
| ส่งข้อความแชท | 30 ข้อความ/นาที และ 20 ห้องใหม่/วัน |
| ค้นหา | 60 ครั้ง/นาที |
| อัปโหลดรูป | 100 ไฟล์/ชม. |
| สร้างออเดอร์ | 20 ครั้ง/ชม. |
| ขอถอนเงิน | 3 ครั้ง/วัน |
| รายงานเนื้อหา | 20 ครั้ง/วัน |
| API สาธารณะทั่วไป | 600 ครั้ง/นาที/IP |

เมื่อโดนจำกัด ตอบ 429 พร้อม `Retry-After` และแสดงข้อความว่าจะลองใหม่ได้เมื่อไร
ไม่ใช่แค่ "มีคำขอมากเกินไป"
