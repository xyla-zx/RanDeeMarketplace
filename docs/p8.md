## 13. กฎธุรกิจ

### 13.1 กฎการโพสต์

1. ผู้ใช้หนึ่งคนมีได้ **หนึ่งร้าน** เปลี่ยน slug ได้ 1 ครั้งต่อ 90 วัน
2. โพสต์ต้องมีรูปอย่างน้อย 1 รูป และผ่านการตรวจภาพอัตโนมัติก่อนเผยแพร่
3. อายุโพสต์ 60 วัน ระบบเตือนก่อนหมดอายุ 5 วันและ 1 วัน ต่ออายุได้ไม่จำกัด
4. โควตาโพสต์ที่เผยแพร่พร้อมกัน: ฟรี 30 · Pro 300 · Business ไม่จำกัด
5. ห้ามโพสต์ซ้ำ: ถ้าชื่อ + ราคา + หมวด เหมือนโพสต์ที่ยังเผยแพร่อยู่ในร้านเดียวกัน
   ให้ปฏิเสธพร้อมลิงก์ไปโพสต์เดิม
6. แก้ราคาได้อิสระ แต่ถ้าขึ้นราคาเกิน 30% ภายใน 24 ชม. ระบบบันทึกไว้ตรวจสอบ
   และไม่ให้แสดงป้าย "ลดราคา" เป็นเวลา 7 วัน
7. ดันฟรี 1 ครั้ง/โพสต์/วัน ดันแล้ว `bumpedAt` เปลี่ยน แต่ไม่เปลี่ยน `publishedAt`
8. โพสต์ที่มีออเดอร์ค้างอยู่ ห้ามลบ ให้ปิดการขายได้อย่างเดียว
9. สินค้าต้องห้าม (รายการในหัวข้อ 14.2) ถูกบล็อกตั้งแต่ตอนกดเผยแพร่

**ตารางสิทธิ์การเปลี่ยนสถานะ**

| จาก | ไป | ใครทำได้ | เงื่อนไข |
|---|---|---|---|
| AWAITING_PAYMENT | PAID | ระบบ (webhook) | ตรวจลายเซ็นผ่าน ยอดตรง |
| AWAITING_PAYMENT | CANCELLED | ผู้ซื้อ, ระบบ | ก่อนจ่าย หรือหมดเวลา 15 นาที |
| PAID | ACCEPTED | ผู้ขาย | ภายใน 24 ชม. |
| PAID | CANCELLED | ผู้ขาย, ผู้ซื้อ, ระบบ | ผู้ขายยกเลิกนับเป็นคะแนนลบ |
| ACCEPTED | PACKED | ผู้ขาย | |
| PACKED | SHIPPED | ผู้ขาย | ต้องมีเลขพัสดุที่ถูกรูปแบบของ carrier |
| SHIPPED | DELIVERED | ระบบ (webhook), ผู้ซื้อ | |
| DELIVERED | COMPLETED | ผู้ซื้อ, ระบบ (7 วัน) | |
| DELIVERED | DISPUTED | ผู้ซื้อ | ภายใน 7 วันเท่านั้น |
| SHIPPED | DISPUTED | ผู้ซื้อ | เฉพาะเหตุ "ไม่ได้รับ" และเกิน ETA 5 วัน |
| DISPUTED | REFUNDED / COMPLETED | SUPPORT, ADMIN | ต้องมีเหตุผลและบันทึก audit |

**กฎการยกเลิก**
- ผู้ซื้อยกเลิกเองได้ก่อนสถานะ `ACCEPTED` เท่านั้น หลังจากนั้นต้องขอผ่านแชท
- ผู้ขายยกเลิกได้ทุกสถานะก่อน `SHIPPED` แต่ทุกครั้งกระทบ `cancelRate` ของร้าน
  ถ้า `cancelRate` เกิน 10% ใน 30 วัน ระบบลดอันดับร้านในฟีดและแจ้งเตือนเจ้าของ
- ยกเลิกทุกกรณีต้องคืนสต็อกทันทีใน transaction เดียวกัน

### 13.3 การคำนวณเงิน

```
ยอดสินค้า      = Σ (ราคาต่อชิ้น × จำนวน)
ส่วนลด        = คูปองร้าน + คูปองแพลตฟอร์ม (ซ้อนกันได้สูงสุด 2 ใบ, ร้านละ 1 ใบ)
ค่าส่ง         = ตามตารางของร้าน หรือ 0 ถ้ายอดถึงเกณฑ์ส่งฟรี
ค่าธรรมเนียม COD = 3% ของยอดรวม ขั้นต่ำ 20 บาท (ผู้ซื้อจ่าย)
ยอดชำระ       = ยอดสินค้า − ส่วนลด + ค่าส่ง + ค่าธรรมเนียม COD

ค่าธรรมเนียมแพลตฟอร์ม = (ยอดสินค้า − ส่วนลดที่ร้านออกเอง) × commissionBps / 10000
ค่าธรรมเนียมเกตเวย์    = ยอดชำระ × 3.65% (เฉพาะบัตร/พร้อมเพย์ ไม่คิดกับ COD)
ยอดผู้ขายได้รับ       = ยอดชำระ − ค่าธรรมเนียมแพลตฟอร์ม − ค่าธรรมเนียมเกตเวย์
                       (ค่าส่งคืนผู้ขายเต็มจำนวน ไม่หักค่าธรรมเนียม)
```

- ปัดเศษทุกค่าธรรมเนียม **ลง** ส่วนต่างเป็นของผู้ขาย
- ส่วนลดจากคูปองแพลตฟอร์ม แพลตฟอร์มเป็นผู้ออก ไม่หักจากผู้ขาย
- ทุกการเคลื่อนไหวของเงินต้องสร้าง `LedgerEntry` คู่กันเสมอ และผลรวมต้องตรงกับ `Wallet`
  มี job ตรวจยอดทุกคืน ถ้าไม่ตรงให้ล็อกกระเป๋าและแจ้งทีมการเงินทันที

### 13.4 ระบบพักเงิน (escrow)

1. ผู้ซื้อจ่าย → เงินเข้า `pendingSatang` ของร้าน พร้อม `LedgerEntry: SALE_ESCROW`
2. ปล่อยเงินเมื่อ: ผู้ซื้อกดรับของ **หรือ** ครบ 7 วันหลัง `DELIVERED` **หรือ** แอดมินสั่งปล่อย
3. ปล่อยแล้วย้ายจาก `pending` → `available` พร้อม `SALE_RELEASE`
4. เปิดข้อพิพาทระหว่างพัก → หยุดตัวนับ ห้ามถอนยอดส่วนนั้น
5. COD: เงินไม่ผ่านระบบ แต่ยังเก็บค่าธรรมเนียมแพลตฟอร์มโดยหักจาก `available` ที่มีอยู่
   ถ้าไม่พอให้ติดยอดค้าง `negativeBalance` และห้ามถอนจนกว่าจะเคลียร์

### 13.5 การถอนเงิน

- ขั้นต่ำ 200 บาท ค่าธรรมเนียมโอน 15 บาท/ครั้ง (ฟรีเดือนละ 1 ครั้งสำหรับแผน Pro ขึ้นไป)
- ต้องยืนยัน OTP ทุกครั้ง และบัญชีธนาคารต้องชื่อตรงกับผู้ยืนยันตัวตน
- คำขอก่อน 14:00 ของวันทำการ → เข้าบัญชีภายในวันถัดไป, หลังจากนั้น → +2 วันทำการ
- เมื่อยื่นคำขอ ให้ย้ายยอดไป `reservedSatang` ทันทีเพื่อกันถอนซ้ำ
- ถ้าโอนไม่สำเร็จ ให้คืนยอดกลับ `available` พร้อมเหตุผลที่อ่านเข้าใจได้

### 13.6 การจัดอันดับในฟีดและการค้นหา

คะแนนรวมของโพสต์ (คำนวณตอน index และคำนวณซ้ำทุก 6 ชั่วโมง):

```
score =  0.30 × ความสด (freshness)
       + 0.20 × คุณภาพร้าน (shopQuality)
       + 0.18 × ความเกี่ยวข้องกับคำค้น (textRelevance)   [เฉพาะหน้าค้นหา]
       + 0.12 × ความน่าสนใจ (engagement)
       + 0.10 × ความใกล้ (proximity)                     [ถ้ามีพิกัด]
       + 0.10 × คุณภาพโพสต์ (contentQuality)

freshness      = exp(-ชั่วโมงตั้งแต่ bumpedAt / 72)
shopQuality    = 0.5×normalized(ratingAvg) + 0.3×shipOnTimeRate + 0.2×responseRate
engagement     = normalized(saveCount×3 + chatCount×5 + viewCount×0.1) แบบ log scale
proximity      = 1 − min(ระยะทางกม. / 50, 1)
contentQuality = จำนวนรูป(สูงสุด 0.3) + ความยาวคำอธิบาย(0.2) + ครบคุณสมบัติ(0.3)
                 + มีตัวเลือกย่อย(0.1) + มีน้ำหนัก/ขนาด(0.1)
```

กฎเพิ่มเติม:
- โพสต์ที่ `boostUntil > now` ขึ้นก่อนเสมอ แต่ไม่เกิน 3 ชิ้นต่อ 20 ชิ้นในฟีด
  และต้องมีป้าย "โปรโมท" ชัดเจน (กฎหมายโฆษณา)
- ร้านเดียวกันขึ้นติดกันได้ไม่เกิน 2 ชิ้น ต้องสลับร้านอื่นคั่น
- โพสต์ที่ `moderationState = FLAGGED` ไม่เข้าฟีด แต่ยังเข้าถึงผ่านลิงก์ตรงได้
- ร้านที่ถูกระงับ โพสต์หายจากฟีดทันทีโดยไม่ต้อง reindex ทีละชิ้น (กรองตอน query)

## 14. ความปลอดภัยของเนื้อหาและการตรวจสอบ

### 14.1 ขั้นตอนการตรวจ

```
ผู้ใช้กดเผยแพร่
   ↓
① ตรวจข้อความ: คำต้องห้าม, เบอร์โทร/LINE ID ในคำอธิบาย (เตือน ไม่บล็อก),
   ลิงก์ภายนอก (บล็อกถ้าเป็นโดเมนในบัญชีดำ), ราคาผิดปกติ
   ↓
② ตรวจรูป: เนื้อหาผู้ใหญ่, ความรุนแรง, ภาพซ้ำจากร้านอื่น (perceptual hash)
   ↓
③ คำนวณ riskScore 0-1
   ↓
   < 0.3  → AUTO_APPROVED เผยแพร่ทันที
   0.3-0.7 → เผยแพร่ทันทีแต่เข้าคิว PENDING_REVIEW ให้คนดูภายใน 24 ชม.
   > 0.7  → ไม่เผยแพร่ เข้าคิวทันที แจ้งผู้ขายว่ากำลังตรวจสอบ
```

### 14.2 สินค้าต้องห้าม (บล็อกอัตโนมัติ)

อาวุธปืนและกระสุน · วัตถุระเบิด · ยาเสพติดและอุปกรณ์เสพ · ยาที่ต้องมีใบสั่งแพทย์ ·
สัตว์ป่าคุ้มครองและซากสัตว์ · อวัยวะมนุษย์ · เอกสารราชการปลอม · บัตรประชาชน/พาสปอร์ต ·
บัญชีธนาคารและซิมที่ลงทะเบียนแล้ว · สื่อลามก · สินค้าละเมิดลิขสิทธิ์และของปลอม ·
บุหรี่ไฟฟ้า · เครื่องดักฟัง · ซอฟต์แวร์เถื่อนและคีย์ละเมิด · สลากกินแบ่งเกินราคา ·
บริการทางเพศ · สินค้าที่อ้างรักษาโรคโดยไม่มี อย.

### 14.3 การป้องกันการฉ้อโกง

สัญญาณที่ต้องเฝ้าระวังและคะแนนความเสี่ยง:

| สัญญาณ | น้ำหนัก |
|---|---|
| บัญชีอายุน้อยกว่า 24 ชม. แล้วโพสต์ของราคาสูง (> 20,000 บาท) | สูง |
| ราคาต่ำกว่าค่ากลางของหมวดเกิน 70% | สูง |
| รูปตรงกับโพสต์ของร้านอื่น (perceptual hash) | สูง |
| ชักชวนคุยนอกแพลตฟอร์มในข้อความแรก | กลาง |
| ขอให้โอนตรงเข้าบัญชีส่วนตัว | สูงมาก — ระงับทันทีและแจ้งผู้ซื้อ |
| เปลี่ยนบัญชีธนาคารแล้วขอถอนทันที | สูง — หน่วงการถอน 72 ชม. |
| หลาย ๆ บัญชีจากอุปกรณ์เดียวกัน | กลาง |
| อัตรายกเลิกออเดอร์สูงผิดปกติ | กลาง |
| รีวิวจากบัญชีที่สร้างใหม่และซื้อจากร้านเดียวกันหลายครั้ง | สูง |

การกระทำอัตโนมัติ: หน่วงการถอนเงิน, ซ่อนโพสต์จากฟีด, ต้องยืนยันตัวตนเพิ่ม, เข้าคิวตรวจ
**ห้ามลบบัญชีหรือยึดเงินอัตโนมัติ** ต้องมีคนตัดสินใจเสมอ

### 14.4 การอุทธรณ์

- ทุกการระงับต้องมีปุ่มอุทธรณ์ในหน้าที่แจ้ง
- ผู้ใช้เขียนคำชี้แจงได้ 1,000 ตัวอักษรและแนบรูปได้ 5 รูป
- ต้องตอบภายใน 3 วันทำการ ถ้าเกินให้คืนสถานะอัตโนมัติสำหรับกรณีที่ไม่ร้ายแรง
- แอดมินคนที่ระงับห้ามเป็นคนพิจารณาอุทธรณ์เคสเดียวกัน

## 15. ความปลอดภัยระบบ

### 15.1 รายการบังคับ

1. รหัสผ่านแฮชด้วย argon2id (m=19456, t=2, p=1) ห้ามใช้ bcrypt/MD5/SHA
2. Session token สุ่ม 32 ไบต์ เก็บเฉพาะค่าที่แฮชแล้วในฐานข้อมูล
3. คุกกี้: `HttpOnly` `Secure` `SameSite=Lax` (`Strict` สำหรับหลังบ้าน)
4. CSRF: ใช้ Server Action ที่มี origin check ของ Next.js และ double-submit token สำหรับ REST
5. ทุก input ผ่าน Zod ทุก output ที่เป็น HTML ผ่าน sanitizer (`isomorphic-dompurify`)
6. คำอธิบายสินค้ารองรับ markdown จำกัด: ตัวหนา เอียง รายการ ลิงก์ ย่อหน้า เท่านั้น
   ลิงก์ทุกอันใส่ `rel="nofollow ugc noopener"` และเปิดแท็บใหม่
7. อัปโหลดไฟล์: ตรวจ magic bytes ไม่เชื่อ extension, ถอด EXIF ทิ้ง (โดยเฉพาะ GPS),
   เสิร์ฟจากโดเมนแยกที่ไม่มีคุกกี้
8. ข้อมูลอ่อนไหว (เลขบัญชี เลขบัตรประชาชน) เข้ารหัสด้วย AES-256-GCM คีย์แยกจาก DB
   แสดงผลเป็นรูปแบบปิดบังเสมอ เช่น `xxx-x-x1234-x`
9. หน้าหลังบ้านบังคับ 2FA สำหรับทุก role ตั้งแต่ MODERATOR ขึ้นไป
10. ทุก webhook ตรวจลายเซ็นและ timestamp (กันการเล่นซ้ำภายใน 5 นาที)
11. ห้าม log: รหัสผ่าน, OTP, token, เลขบัตร, เลขบัญชี — ใช้ redactor ใน Pino
12. Security headers:

```
Content-Security-Policy: default-src 'self';
  img-src 'self' data: blob: https://cdn.randee.app;
  script-src 'self' 'nonce-{random}';
  style-src 'self' 'unsafe-inline';
  connect-src 'self' https://api.randee.app wss://rt.randee.app;
  frame-ancestors 'none'; base-uri 'self'; form-action 'self'
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(self), camera=(self), microphone=()
```

### 15.2 PDPA

- ขอความยินยอมแยกรายการ: จำเป็นต่อบริการ / วิเคราะห์การใช้งาน / การตลาด
- บันทึกเวลาและเวอร์ชันของนโยบายที่ยินยอม
- ผู้ใช้ขอสำเนาข้อมูลได้ ระบบสร้างไฟล์ JSON + รูปภาพเป็น zip ภายใน 7 วัน
- ขอลบบัญชี: ระงับทันที ลบจริงหลัง 30 วัน ยกเว้นข้อมูลที่กฎหมายบังคับให้เก็บ
  (ใบเสร็จ ธุรกรรม เก็บ 5 ปี แต่ตัดการเชื่อมโยงกับตัวบุคคล)
- ข้อมูลผู้เยาว์: ไม่อนุญาตให้ผู้ที่อายุต่ำกว่า 18 ปีเปิดร้าน ต้องยืนยันวันเกิดตอนยืนยันตัวตน
