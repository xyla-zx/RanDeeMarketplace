# PROMPT.md — ระบบโพสต์ร้านค้า "ร้านดี" (RanDee Marketplace)

> ไฟล์นี้คือ **master prompt** ฉบับสมบูรณ์สำหรับสั่งให้ AI agent (Claude Code / Cursor / Codex)
> สร้างระบบโพสต์ร้านค้าแบบครบวงจรตั้งแต่ศูนย์จนขึ้น production ได้จริง
> อ่านทั้งไฟล์ก่อนเขียนโค้ดบรรทัดแรกเสมอ

## 0. วิธีใช้ไฟล์นี้

### 0.1 สำหรับมนุษย์

1. วางไฟล์นี้ไว้ที่ root ของ repository ในชื่อ `PROMPT.md`
2. เปิด agent แล้วสั่ง: `อ่าน PROMPT.md ทั้งไฟล์ แล้วทำตาม Milestone ทั้งหมดให้เสร็จรวดเดียว` 
3. ให้ agent รันงานเฟสต่อเฟสยาวๆ ต่อเนื่องจนจบระบบโดยไม่ต้องหยุดพัก
4. หลังจบแต่ละ Milestone ให้รัน `pnpm verify` และเช็ค Acceptance Checklist ของ Milestone นั้นโดยอัตโนมัติก่อนเริ่ม Milestone ถัดไป
5. ถ้า agent ถามคำถาม ให้ตอบโดยอ้างอิงหมายเลขหัวข้อในไฟล์นี้ อย่าตอบแบบเปิดกว้าง

### 0.2 สำหรับ AI agent

- ไฟล์นี้คือ **source of truth** เดียว ถ้าสิ่งที่คุณจำได้ขัดกับไฟล์นี้ ให้เชื่อไฟล์นี้
- ห้ามถามคำถามที่ไฟล์นี้ตอบไว้แล้ว ให้ค้นด้วยหมายเลขหัวข้อก่อน
- ถ้ามีจุดที่ไฟล์นี้ไม่ได้ระบุ ให้ **ตัดสินใจเอง** ตามหลักการในหัวข้อ 1.3 แล้วบันทึกการตัดสินใจลง `docs/decisions/ADR-XXX.md`
- ห้ามสร้าง placeholder ที่ทำงานไม่ได้ ห้ามเขียน `// TODO: implement later` ในโค้ดที่ส่งมอบ
- ทุกฟีเจอร์ต้องมี: happy path + empty state + loading state + error state + mobile layout ครบ 5 อย่าง
- เขียน commit เป็นภาษาอังกฤษ รูปแบบ Conventional Commits

## 1. บทบาทและหลักการ

### 1.1 บทบาทของคุณ

คุณคือ **Lead Full-stack Engineer + Design Lead** ของสตูดิโอที่ขึ้นชื่อเรื่อง
"งานที่ไม่มีวันถูกเข้าใจผิดว่าเป็นของเจ้าอื่น" ลูกค้ารายนี้เคยปฏิเสธข้อเสนอที่ดู
templated มาแล้วสองรอบ เขาจ่ายเงินเพื่อ **มุมมองการออกแบบที่ชัดเจนและกล้าตัดสินใจ**
ไม่ใช่เพื่อ dashboard สำเร็จรูปที่เปลี่ยนโลโก้ก็ใช้กับธุรกิจไหนก็ได้

คุณรับผิดชอบทั้ง:
- สถาปัตยกรรมระบบและคุณภาพโค้ด
- ระบบดีไซน์และรายละเอียดภาพทุกพิกเซล
- คำพูดทุกคำใน interface (microcopy)

### 1.2 เป้าหมายของผลิตภัณฑ์

> ให้พ่อค้าแม่ค้าไทยเปิดร้านและโพสต์ของขายได้ภายใน **3 นาที** จากมือถือเครื่องเดียว
> และให้คนซื้อหาของที่ต้องการเจอภายใน **3 ครั้งแตะ**

ทุกการตัดสินใจด้านฟีเจอร์และดีไซน์ต้องตอบคำถามว่า "มันทำให้สองตัวเลขนี้ดีขึ้นไหม"
ถ้าไม่ ให้ตัดทิ้งหรือย้ายไป Phase 2

### 1.3 หลักการตัดสินใจเมื่อสเปกไม่ครอบคลุม

เรียงลำดับความสำคัญจากบนลงล่าง เมื่อขัดกันให้ข้อบนชนะ:

1. **ความปลอดภัยของเงินและข้อมูลผู้ใช้** — ถ้าเสี่ยง ให้เลือกทางที่ปลอดภัยกว่าเสมอ
2. **ความถูกต้องของข้อมูล** — ยอมช้าแต่ห้ามผิด โดยเฉพาะ stock, ยอดเงิน, สถานะออเดอร์
3. **ความเร็วในการใช้งานจริงบนมือถือ 4G** — ลดจำนวนคลิก ลดขนาด payload
4. **ความชัดเจนของ interface** — ถ้าต้องเลือกระหว่าง "สวย" กับ "เข้าใจง่าย" เลือกเข้าใจง่าย
5. **ความสม่ำเสมอกับ design system** — ห้ามสร้าง pattern ใหม่ถ้ามีของเดิมใช้ได้
6. **ความง่ายในการดูแลรักษาโค้ด**

### 1.4 สิ่งที่ห้ามทำในงานออกแบบ (anti-pattern ที่พบบ่อย)

ทั้งหมดนี้คือค่า default ที่เครื่องมือ generate ออกมาเหมือนกันหมด ห้ามใช้:

- พื้นหลังครีมอุ่น (#F4F1EA) คู่กับ serif ตัวใหญ่และ accent สีดินเผา (#D97757)
- พื้นดำสนิทคู่กับ accent สีเขียวสะท้อนแสงหรือส้มแสบตาเพียงสีเดียว
- eyebrow label ตัวพิมพ์ใหญ่ทั้งหมดวางเหนือทุกหัวข้อ
- meta string คั่นด้วยจุดกลาง เช่น `A · B · C`
- ใส่ลูกศร `→` ต่อท้ายข้อความปุ่ม
- เน้นคำเดียวในพาดหัวด้วยสีหรือ italic
- การ์ดขอบมนเท่ากันหมดทั้งหน้า เงาเทาอ่อนเหมือนกันทุกใบ
- เลขลำดับ 01 / 02 / 03 ประดับเนื้อหาที่ไม่ได้เป็นลำดับขั้นจริง
- gradient พาดพื้นหลังเพื่อความสวยอย่างเดียว
- ตัวเลขใหญ่ + label เล็ก + gradient เป็น hero ของหน้า

## 2. ภาพรวมระบบ

### 2.1 หนึ่งย่อหน้าอธิบายระบบ

RanDee คือแพลตฟอร์มโพสต์ร้านค้าแบบ multi-vendor ที่รวม 3 อย่างเข้าด้วยกัน:
(1) **หน้าร้านส่วนตัว** ที่ผู้ขายแต่งเองได้และมี URL ของตัวเอง
(2) **ฟีดประกาศขาย** ที่คนซื้อเลื่อนดู ค้นหา และกรองตามหมวด ราคา ระยะทาง
(3) **ระบบซื้อขายครบวงจร** ตั้งแต่แชทต่อรอง เช็คเอาต์ พร้อมเพย์/บัตร/เก็บเงินปลายทาง
ออกใบจัดส่ง ติดตามพัสดุ รีวิว ไปจนถึงการโอนเงินเข้าบัญชีผู้ขาย
มีระบบหลังบ้านสำหรับผู้ดูแลจัดการเนื้อหา ข้อพิพาท และการเงินครบถ้วน

## 3. กลุ่มผู้ใช้

### 3.1 Persona A — "พี่หน่อย" ผู้ขายรายย่อย (ผู้ใช้หลัก 70%)

- อายุ 32 ขายเสื้อผ้ามือสองจากที่บ้าน ใช้มือถือ Android ราคากลาง หน้าจอ 6.1 นิ้ว
- ถ่ายรูปด้วยมือถือ โพสต์ตอนดึกหลังลูกหลับ มีเวลาครั้งละ 10-15 นาที
- **เจ็บปวดที่สุด**: ต้องกรอกฟอร์มยาว ต้องรอโหลด ต้องสลับแอปไปมา
- **ต้องการ**: โพสต์เร็ว รูปสวยโดยไม่ต้องแต่ง ลูกค้าทักแล้วได้ยินเสียงเตือน
- **สิ่งที่ระบบต้องทำให้**: ฟอร์มโพสต์แบบ 3 ขั้น บันทึกร่างอัตโนมัติทุก 5 วินาที
  อัปโหลดรูปพร้อมกัน 10 รูปแบบ resume ได้ ตัดขอบรูปอัตโนมัติเป็น 4:5

### 3.2 Persona B — "คุณเบส" ผู้ซื้อ (ผู้ใช้หลัก 25%)

- อายุ 26 พนักงานออฟฟิศ เลื่อนหาของตอนพักเที่ยงและก่อนนอน
- **เจ็บปวดที่สุด**: ไม่รู้ว่าร้านไหนเชื่อถือได้ กลัวโอนแล้วไม่ได้ของ
- **ต้องการ**: เห็นคะแนนร้าน เห็นว่ามีคนซื้อจริง จ่ายแล้วเงินไม่ถึงร้านทันที
- **สิ่งที่ระบบต้องทำให้**: ป้ายยืนยันตัวตนร้าน ประวัติการขาย รีวิวที่ซื้อจริงเท่านั้น
  ระบบพักเงิน (escrow) จนกดรับของ

### 3.3 Persona C — "ทีมแอดมิน" ผู้ดูแล (ผู้ใช้ 5%)

- ดูแลคิวรายงานวันละ 200-400 รายการ ใช้คอมพิวเตอร์จอกว้าง
- **ต้องการ**: คิวงานเดียวจบ คีย์ลัดครบ เห็นบริบทครบโดยไม่ต้องเปิดแท็บใหม่

### 3.5 ขอบเขตที่ "ไม่ทำ" ในเวอร์ชันนี้

เขียนไว้ชัดเพื่อกันงานบานปลาย:

- ไม่มีระบบประมูล
- ไม่มีวิดีโอสด (live commerce)
- ไม่มีแอป native (ใช้ PWA แทน)
- ไม่มีระบบ dropship หรือเชื่อมคลังสินค้าภายนอก
- ไม่มีสกุลเงินอื่นนอกจากบาท
- ไม่มีการจัดส่งข้ามประเทศ
- ไม่มีระบบพันธมิตร (affiliate)
