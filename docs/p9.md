## 16. การเข้าถึง (Accessibility)

เป้าหมาย WCAG 2.2 ระดับ AA ทุกหน้า ไม่มีข้อยกเว้น

### 16.1 รายการตรวจบังคับ

1. โครงสร้างหัวข้อเรียงลำดับ h1 → h2 → h3 ไม่ข้ามระดับ หนึ่งหน้ามี h1 เดียว
2. ทุกหน้ามี landmark: `header` `nav` `main` `aside` `footer` และลิงก์ข้ามไปเนื้อหาหลัก
3. อัตราส่วนความต่างสี: ข้อความปกติ ≥ 4.5:1, ข้อความใหญ่ ≥ 3:1, ขอบ UI ≥ 3:1
   (ตรวจทุกคู่สีใน token ด้วยสคริปต์ `pnpm check:contrast` ใน CI)
4. focus ring มองเห็นได้ทุกองค์ประกอบ ห้าม `outline: none` โดยไม่มีตัวแทน
5. ลำดับ tab ตรงกับลำดับการอ่าน ไม่มี `tabindex` บวก
6. Dialog/Sheet: ขังโฟกัสไว้ข้างใน, Esc ปิด, คืนโฟกัสกลับปุ่มที่เปิด, `aria-modal="true"`
7. ฟอร์ม: `label` ผูกกับ input ทุกช่อง, ข้อผิดพลาดผูกด้วย `aria-describedby`
   และประกาศผ่าน `aria-live="assertive"`
8. รูปสินค้า: `alt` มาจากชื่อโพสต์ + ลำดับรูป, รูปประดับใส่ `alt=""`
9. ไอคอนเดี่ยวต้องมี `aria-label` ที่เป็นคำกริยา เช่น "บันทึกโพสต์นี้"
10. ตัวนับ/สถานะที่เปลี่ยนเอง ใช้ `aria-live="polite"`
11. เคารพ `prefers-reduced-motion` และ `prefers-contrast`
12. แตะได้ขั้นต่ำ 44x44 px ระยะห่างระหว่างปุ่มอย่างน้อย 8px
13. ขยายตัวอักษรถึง 200% ต้องไม่มีเนื้อหาหาย ไม่มี scroll แนวนอน
14. ทดสอบจริงด้วย NVDA (Windows) และ VoiceOver (iOS) กับ 5 เส้นทางหลัก

### 16.2 คีย์ลัดทั่วระบบ

```
/           โฟกัสช่องค้นหา
g h         ไปหน้าแรก
g f         ไปฟีด
g o         ไปออเดอร์ของฉัน
g c         ไปแชท
g s         ไปหลังบ้านร้าน
n           สร้างโพสต์ใหม่ (ถ้ามีร้าน)
Esc         ปิด overlay ที่เปิดอยู่
?           แสดงรายการคีย์ลัด
```

ต้องปิดคีย์ลัดอัตโนมัติเมื่อโฟกัสอยู่ในช่องกรอกข้อความ

### 17.2 วิธีที่ต้องทำ

- รูปทั้งหมดผ่าน `next/image` มี `sizes` ถูกต้อง เสิร์ฟ AVIF ก่อน WebP ก่อน JPEG

- ฟอนต์: subset เฉพาะอักษรไทย+ละตินพื้นฐาน, `font-display: swap`, preload 2 น้ำหนัก

- ฟีดใช้ virtualization เมื่อเกิน 60 รายการ
- ทุก query ที่หน้าใช้ต้องมี index รองรับ ตรวจด้วย `EXPLAIN ANALYZE` ในการรีวิว
- ห้าม N+1: ใช้ `include`/`select` ให้ครบ และตรวจด้วย middleware นับ query ในโหมด dev
  ถ้าหน้าไหนยิงเกิน 12 query ให้ CI เตือน
- เชื่อมต่อฐานข้อมูลผ่าน connection pool ที่จำกัดจำนวน (pgbouncer ใน production)

## 18. SEO

1. ทุกหน้าสาธารณะ render ฝั่งเซิร์ฟเวอร์ ไม่มีเนื้อหาสำคัญที่ต้องรอ JS
2. `title` ไม่เกิน 60 ตัวอักษร รูปแบบ: `{ชื่อโพสต์} - {ชื่อร้าน} | RanDee`
3. `description` 120-155 ตัวอักษร สร้างจากคำอธิบายจริง ไม่ใช่ข้อความสำเร็จรูป
4. URL: `/p/{slug}-{shortId}` โดย slug มาจากชื่อไทยแปลงเป็น latin แบบอ่านออก
   ถ้าชื่อเปลี่ยน ให้ redirect 301 จาก slug เดิม
5. Structured data (JSON-LD) ตามชนิดหน้า:
   - โพสต์: `Product` + `Offer` (price, availability, priceCurrency THB) + `AggregateRating` + `Brand`
   - ร้าน: `Store` + `LocalBusiness` (ถ้าเปิดเผยที่ตั้ง) + `openingHoursSpecification`
   - หมวด: `CollectionPage` + `BreadcrumbList`
   - ช่วยเหลือ: `FAQPage`
6. `canonical` ทุกหน้า, หน้าค้นหาและหน้าที่มีตัวกรองใส่ `noindex, follow`
7. `hreflang` สำหรับ th/en คู่กับ `x-default`
8. Sitemap แยกไฟล์: `sitemap-listings-{n}.xml` (5 หมื่นรายการ/ไฟล์), `sitemap-shops.xml`,
   `sitemap-categories.xml`, `sitemap-pages.xml` อัปเดตทุก 6 ชั่วโมง
9. รูป OG สร้างอัตโนมัติด้วย `next/og`: รูปสินค้า + ป้ายราคาทรงตั๋ว + ชื่อร้าน
   ขนาด 1200x630 พื้นขาว ขอบครามตามระบบดีไซน์
10. `robots.txt` ปิด `/admin`, `/seller`, `/checkout`, `/api`, `/search`
11. หน้าโพสต์ที่ขายแล้วให้คง URL ไว้ (ไม่ 404) ใส่ `availability: SoldOut` และแนะนำของคล้ายกัน

### 21.2 เส้นทาง E2E บังคับ

```
E1  สมัครด้วยเบอร์ → ยืนยัน OTP → ตั้งชื่อ → เข้าหน้าแรก
E2  เปิดร้าน → โพสต์สินค้าพร้อม 3 รูปและ 2 ตัวเลือก → เผยแพร่ → เห็นในฟีด

E5  ใส่ตะกร้าจาก 2 ร้าน → เช็คเอาต์ → แยกเป็น 2 ออเดอร์ → จ่ายพร้อมเพย์ (mock)
E6  ผู้ขายรับออเดอร์ → กรอกเลขพัสดุ → ผู้ซื้อเห็นสถานะเปลี่ยน

E10 ผู้ใช้รายงานโพสต์ → แอดมินระงับ → โพสต์หายจากฟีด → เจ้าของเห็นเหตุผลและอุทธรณ์ได้
E11 เปิดข้อพิพาท → แอดมินสั่งคืนเงินบางส่วน → ยอดถูกต้องทั้งสองฝั่ง
E12 ใช้คีย์บอร์ดอย่างเดียวตั้งแต่หน้าแรกจนสั่งซื้อสำเร็จ
```

### 21.3 เคสขอบที่ต้องมีเทสต์เฉพาะ

- ซื้อพร้อมกัน 2 คน ของเหลือ 1 ชิ้น — ต้องมีคนเดียวที่ได้ อีกคนได้ `LISTING_OUT_OF_STOCK`
- จ่ายเงินสำเร็จแต่ webhook มาซ้ำ 3 ครั้ง — ต้องไม่เพิ่มเงินซ้ำ
- ถอนเงิน 2 ครั้งพร้อมกันเกินยอด — ต้องสำเร็จครั้งเดียว
- ผู้ขายลบโพสต์ระหว่างที่ผู้ซื้ออยู่ในหน้าเช็คเอาต์
- คูปองหมดอายุระหว่างเช็คเอาต์
- เปลี่ยนราคาระหว่างที่มีข้อเสนออยู่
- ผู้ซื้อกดรับของพร้อมกับระบบปล่อยเงินอัตโนมัติวินาทีเดียวกัน

รวมเวลาต้องไม่เกิน 12 นาที ถ้าเกินให้แยก job ขนานเพิ่ม

### 23.3 ข้อกำหนดการ deploy

- Migration ต้อง backward compatible เสมอ (เพิ่มคอลัมน์ก่อน, ใช้ทีหลัง, ลบในรอบถัดไป)
- ห้าม migration ที่ล็อกตารางนานเกิน 2 วินาที ตารางใหญ่ให้ใช้วิธีเพิ่ม index แบบ `CONCURRENTLY`
- เปิดฟีเจอร์ใหม่ผ่าน feature flag เสมอ ไม่ใช่ผ่าน deploy
- Health check: `/api/health` ตรวจ DB, Redis, Meilisearch, S3 คืน 200 เฉพาะเมื่อพร้อมทั้งหมด
- Rollback ได้ภายใน 5 นาทีด้วยการสลับ image tag
- สำรองฐานข้อมูล: full ทุกวัน เก็บ 30 วัน + WAL ต่อเนื่อง (RPO 5 นาที, RTO 1 ชม.)
- ทดสอบกู้คืนจากสำรองจริงทุกไตรมาส บันทึกผลใน `docs/runbooks/restore-drill.md`

### 23.4 การเฝ้าระวัง

ตั้งการแจ้งเตือนเมื่อ:
- อัตราข้อผิดพลาด 5xx > 1% ใน 5 นาที
- p95 ของ `/api/v1/search` > 800ms
- คิว BullMQ ค้างเกิน 1,000 งาน
- `OutboxEvent` ที่ยังไม่ส่งมีอายุเกิน 5 นาที
- ยอด Wallet รวมไม่ตรงกับ LedgerEntry (ตรวจทุกคืน)
- อัตราการจ่ายเงินสำเร็จต่ำกว่า 92% ใน 15 นาที
- พื้นที่ดิสก์ฐานข้อมูลเหลือ < 20%

## 24. ลำดับการสร้าง (Milestones)

ทำตามลำดับนี้เท่านั้น แต่ละขั้นต้องส่งมอบของที่ใช้งานได้จริง ไม่ใช่โครงเปล่า

### M0 — รากฐาน (2 วัน)
monorepo, Docker, Prisma schema ครบทั้งไฟล์, migration แรก, seed ขั้นต่ำ,
design token, คอมโพเนนต์พื้นฐาน 12 ตัว, icon set ครบ, layout หลัก, i18n โครง
**ผ่านเมื่อ**: `pnpm verify` ผ่าน และหน้าแรกเปล่าแสดง header/footer ตามดีไซน์ได้

### M1 — บัญชีและร้าน (3 วัน)
สมัคร/เข้าสู่ระบบ/OTP/OAuth, โปรไฟล์, สร้างร้าน, หน้าร้านสาธารณะ, ป้ายหน้าร้าน, ติดตามร้าน
**ผ่านเมื่อ**: E1 ผ่าน และเปิดร้านแล้วเข้า `/s/{slug}` เห็นหน้าร้านจริง

### M2 — โพสต์และสื่อ (4 วัน)
อัปโหลดรูปครบระบบ, ฟอร์มโพสต์ 3 ขั้น, ร่างอัตโนมัติ, ตัวเลือกย่อย, หน้าโพสต์,
จัดการโพสต์ในหลังบ้านร้าน
**ผ่านเมื่อ**: E2 ผ่าน และโพสต์จากมือถือจริงได้ใน 3 นาที

### M3 — ค้นพบและค้นหา (3 วัน)
ฟีด, หมวดหมู่, Meilisearch + ตัดคำไทย, ตัวกรอง, บันทึกการค้นหา, บันทึกโพสต์, จัดอันดับ
**ผ่านเมื่อ**: E3 ผ่าน และค้นคำสะกดผิดยังเจอของ

### M4 — แชทและข้อเสนอ (3 วัน)
ห้องแชท realtime, การ์ดสินค้า/ข้อเสนอ, สถานะอ่าน, กำลังพิมพ์, แจ้งเตือนในแอป
**ผ่านเมื่อ**: E4 ผ่าน และข้อความถึงภายใน 1 วินาที

### M5 — ตะกร้าถึงออเดอร์ (4 วัน)
ตะกร้า, ที่อยู่, ค่าส่ง, เช็คเอาต์, แยกออเดอร์ตามร้าน, จองสต็อก, เครื่องสถานะออเดอร์,
หน้าออเดอร์ทั้งสองฝั่ง
**ผ่านเมื่อ**: E5, E6 ผ่าน และเคสขอบ "ซื้อพร้อมกันของเหลือชิ้นเดียว" ผ่าน

### M6 — ชำระเงินและกระเป๋า (4 วัน)
Omise พร้อมเพย์/บัตร, COD, webhook, escrow, ledger, กระเป๋าเงิน, ถอนเงิน, คืนเงิน
**ผ่านเมื่อ**: E7, E9 ผ่าน และยอด ledger ตรงกับ wallet ทุกเคส

### M7 — ขนส่งและรีวิว (3 วัน)
ตารางค่าส่ง, ใบปะหน้า PDF, ติดตามพัสดุ + webhook, รีวิวและตอบกลับ, คะแนนร้าน
**ผ่านเมื่อ**: E8 ผ่าน และพิมพ์ใบปะหน้า 10 ใบพร้อมกันได้

### M8 — ตรวจสอบและหลังบ้าน (4 วัน)
รายงาน, คิวตรวจสอบพร้อมคีย์ลัด, ระงับ/คืนสถานะ, ข้อพิพาท, อุทธรณ์, audit log,
จัดการหมวด/แบนเนอร์/CMS/flag, สรุปตัวเลข
**ผ่านเมื่อ**: E10, E11 ผ่าน และแอดมินจัดการ 20 เคสได้ใน 10 นาที

### M9 — ขัดเงาและขึ้นระบบ (3 วัน)
การแจ้งเตือนครบทุกช่องทาง, PWA, SEO ครบ, a11y ผ่าน 100, งบประสิทธิภาพผ่าน,
seed เต็ม, เอกสาร runbook, ทดสอบโหลด
**ผ่านเมื่อ**: E12 ผ่าน, Lighthouse ครบเกณฑ์ทุกหน้า, ทดสอบโหลดผ่าน

### Phase 2 (หลังเปิดใช้)
ระบบดันโพสต์แบบเสียเงิน, แผนสมาชิก, สถิติผู้ขายเชิงลึก, คูปองแพลตฟอร์ม,
แอดมินแบบหลายผู้ใช้ต่อร้าน, API สาธารณะ

### 25.3 ข้อผิดพลาด

## ภาคผนวก ข — รูปแบบเลขพัสดุที่ต้องตรวจ

```
ไปรษณีย์ไทย  EMS/ลงทะเบียน   ^[A-Z]{2}\d{9}TH$
Flash Express                ^TH\d{11,13}$
J&T Express                  ^\d{12,14}$
Kerry Express                ^(SHP|KEX)\d{9,12}$
Best Express                 ^\d{12}$
Ninja Van                    ^NVTH\d{9,12}$
```

ถ้าเลขไม่ตรงรูปแบบของ carrier ที่เลือก ให้เตือนแต่ยังบันทึกได้
(ผู้ขายบางรายใช้บริการที่ระบบยังไม่รู้จัก) และทำเครื่องหมายไว้ว่ายังตรวจสอบไม่ได้

## ภาคผนวก ค — สิ่งที่ต้องบันทึกลง ADR

เขียน ADR ทุกครั้งที่ตัดสินใจเรื่องเหล่านี้:
เปลี่ยนเทคโนโลยีในตาราง 4.1 · เปลี่ยนโครงสร้างตารางที่มีข้อมูลจริงแล้ว ·
เพิ่มบริการภายนอกใหม่ · เปลี่ยนสูตรคิดค่าธรรมเนียม · เปลี่ยนสูตรจัดอันดับ ·
เปลี่ยนนโยบายความปลอดภัย · เพิ่ม dependency ที่มีขนาดเกิน 30KB gzip
